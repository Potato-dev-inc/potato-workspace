# How work is routed (plain words)

Always
- Pass my exact words along with the clear version.
- Tell me which way it went. I can change it.
- Cheapest helper that can finish in one go. A failed cheap try costs more.

Ask me first
- Publishing a release, pushing, making a beta public.
- New dependencies. Emptying trash. Anything with logins, lending or money.

Scout first (read-only, short summary)
- Any task where the brief can't yet name the files.

Easy -> worker-easy
- One area, known pattern, every file and string can be listed.
- Copy, style, empty states, a greyed button's reason.

Medium -> worker-medium
- Several files in one layer (screen only, or Rust only).
- A screen rebuilt from an approved mock.
- Time box 90 minutes. If it fails or stalls, give it to worker-hard.

Hard -> worker-hard
- Rust and screen together. More than about 5 files. Unknown cause.
- Anything an agent calls (tools, standbys, run an agent).
- Security: bridge, tokens, consent, devices. The lead reads the diff.

Design -> designer
- Screens, mocks, colour and copy. Light and dark. Show a mock before building.

Checking -> checker
- Real-app check for anything a person clicks or an agent calls.
- At most 2 fix loops, then the lead decides or asks me.
- Branches: light tests only. Full gate once per release.

Split
- Split only when parts touch different files and can be proven alone.
- Never two open branches on the same settings switches or the tool list.
